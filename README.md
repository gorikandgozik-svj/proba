# NEXUS

Социальное приложение на Next.js App Router, TypeScript и Supabase. Первый этап: аккаунты, профили, текстовые публикации, лайки, комментарии, подписки, поиск и две ленты (Mixed и Following). Сортировка — от новых к старым, без ML. Данные доступны только вошедшим пользователям. Другие разделы обозначены как будущие этапы.

## Требования

- Node.js 26 LTS
- npm (поставляется с Node.js)

## Команды

```bash
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run build
```

`npm run check` запускает все четыре проверки. Локальный сервер доступен по адресу http://localhost:3000.

## Backend setup

Создан отдельный Supabase-проект `nexus` (ref: `whxtdqwtjwauinpbbrrq`, eu-west-1). Схема `db/phase1.sql` уже применена к нему как миграция `nexus_phase1`. Не запускайте её повторно в том же проекте. Для другого пустого проекта выполните SQL один раз через SQL Editor.

Скопируйте `.env.example` в `.env.local` и заполните URL и publishable key из Supabase → Connect. Секретный/service-role ключ не нужен. В Codex Cloud добавьте те же две переменные в конфигурацию окружения, выберите Node 26 и setup command `npm ci`.

В Supabase Auth задайте Site URL (`http://localhost:3000` для разработки, HTTPS-домен для будущего deployment). В шаблоне Confirm signup используйте ссылку `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email`. Оставьте подтверждение email включённым. Для реальных пользователей настройте собственный SMTP и ограничения Auth; встроенная отправка имеет ограничения.

Создайте аккаунт, подтвердите email, войдите, заполните профиль. Затем можно публиковать, лайкать и комментировать. Второй аккаунт позволяет проверить подписки и Following. `tests/rls.sql` проверяет социальные операции и RLS в транзакции с полным откатом синтетических данных.

## Deployment and safety

Приложение требует Node-сервера (`npm run build`, затем `npm start`) и двух переменных окружения. Static export не подходит. Подойдёт совместимый Next.js-хостинг; платформа и тариф не подключены, публичный deployment не выполнялся.

RLS защищает каждую таблицу; серверные действия проверяют пользователя через Auth, Zod валидирует ввод, React выводит текст без HTML. База ограничивает публикации до одной за 10 секунд, комментарии — до одного за 5 секунд на пользователя. Ограничения Auth предоставляет Supabase. Перед публичным запуском нужны CAPTCHA/anti-abuse, лимиты чтения и реакций, модерация/жалобы/блокировки, политика возраста и удаления данных, аудит зависимостей и полный email E2E. Текущий milestone предназначен для разработки, а не открытого запуска.

Изображения/Storage, видео, сообщения, сообщества и AI пока не реализованы. Нет демонстрационных пользователей или фиктивных данных. Без backend интерфейс показывает инструкцию подключения.

## Работа с изменениями

Создавайте ветку от `main` для каждой задачи (`feature/<краткое-имя>`), проверяйте `npm run check`, затем открывайте pull request в `main`. CI повторяет эти проверки на PR и после отправки в `main`.
