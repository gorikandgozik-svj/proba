# NEXUS

Единое социальное приложение: профиль, связи и интересы общие для текста, изображений, видео, сообществ и разговоров. Это рабочий MVP для контролируемой разработки и тестирования; публичный запуск не выполнялся.

## Возможности

- Email/password Auth, подтверждение email, редактирование профиля.
- Посты с текстом и одним фото/видео, лайки, комментарии, подписки и поиск.
- Mixed, Following, Video, Discussions и Saved; закладки, скрытие и восстановление постов, явные интересы.
- Сообщества, членство и публикации в общей ленте.
- Уведомления о лайках, комментариях и подписках; жалобы и двусторонняя блокировка контакта.
- Личные и групповые разговоры до 10 участников, обновление каждые 15 секунд при открытой странице.
- Адаптивный интерфейс; системная, светлая и тёмная темы.

Mixed сортирует каждую страницу из 20 постов по свежести (до 48 баллов, минус 1 в час) и выбранным интересам (+12 баллов). Остальные режимы хронологические. ML и платных AI-вызовов нет. AI не добавлен без доступа к провайдеру и разрешения на оплату.

## Запуск

Node.js 26, npm. На этом компьютере backend уже настроен в игнорируемом `.env.local`.

```bash
npm ci
npm run dev
```

Открыть http://localhost:3000. Для нового checkout скопируйте `.env.example` в `.env.local` и заполните URL и publishable key из **отдельного проекта Supabase NEXUS** (`whxtdqwtjwauinpbbrrq`, eu-west-1). Service-role ключ не нужен. Код использует только `gorikandgozik-svj/proba` и этот backend; другие проекты не затрагиваются.

Схема и закрытый bucket уже применены к NEXUS. Не запускайте миграции повторно в этой базе. Для нового пустого backend применяйте `supabase/migrations/` по порядку имён. Подробнее: [миграции](supabase/README.md).

Auth поддерживает стандартный PKCE-редирект с `?code=` и дополнительный endpoint `/auth/confirm` для собственного шаблона с token_hash. При смене адреса приложения настройте Site URL и redirect allowlist в Supabase Auth. Реальную доставку писем/SMTP необходимо проверить отдельно.

## Проверка

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run check
```

GitHub Actions повторяет `npm ci` и `npm run check` для PR и main. Для интеграционных скриптов нужны только специально созданные синтетические аккаунты, их email/password в переменных `NEXUS_TEST_EMAIL_A/B/C`, `NEXUS_TEST_PASSWORD`, а также путь к PNG в `NEXUS_TEST_IMAGE_PATH`:

```bash
node --env-file=.env.local --env-file=.env.test.local tests/backend.integration.mjs
node --env-file=.env.local --env-file=.env.test.local tests/media-messages.integration.mjs
```

Эти скрипты создают реальные тестовые записи. Не используйте личные аккаунты. Удаление синтетических данных и Storage-файлов после прогона — отдельный контролируемый шаг. `tests/rls.sql` выполняет минимальный smoke test с откатом.

## Архитектура и ограничения

App Router + Server Components; серверные действия проверяют пользователя; Supabase Auth/Postgres/Storage; типы базы в `lib/database.types.ts`. Клиентская логика ограничена формами, темой, загрузкой и обновлением разговоров. CSS без дополнительного UI-фреймворка. Все таблицы приложения защищены RLS; ввод проверяется на сервере и ограничениями БД.

Фото: JPEG/PNG/WebP до 8 MB; видео: MP4/WebM до 25 MB. Транскодирования нет; воспроизведение зависит от кодеков браузера. Подписанные ссылки действуют 5 минут. Сообщения не имеют end-to-end шифрования. Данные не заполнены фиктивным контентом.

Для облачной разработки и размещения: [DEPLOYMENT.md](DEPLOYMENT.md). Границы безопасности и подготовка к публичному запуску: [SECURITY.md](SECURITY.md). Результаты проверок: [PROGRESS.md](PROGRESS.md).

Рабочий процесс: feature-ветка → проверки → PR → merge после успешного CI. Не добавляйте ключи или `.env` в Git.
